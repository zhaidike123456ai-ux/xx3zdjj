# 多智能体协作

这是视频处理阶段的默认工作安排；当前用户要求与宿主规则优先。使用宿主已有的子智能体工具，不把 Skill 的 `agents/openai.yaml` 当成能开启多智能体的开关。它只提供技能界面元数据与默认提示，不创建自定义代理。

## 自主决定人数与分工

1. 核对实际加载的 Skill 路径、版本、当前阶段、批准状态，以及会话工具中是否有创建、等待和收集子智能体结果的能力。工具名称随宿主变化，以实际暴露的接口为准；不要虚构函数名或把未暴露的能力说成已开启。
2. 每阶段先判断：独立任务及依赖是什么、素材条数和风险如何、哪些任务需要独立质检、当前槽位与 CPU/GPU/内存允许多少工作。主代理据此自主选人数与职责，不设固定编制，不要求用户报人数。安装检查和简单问答通常自行完成；分析方案及媒体/工程产物仍按下文质检。
3. 有可独立任务且工具可用时调用创建工具。每次委派说明：输入绝对路径、版本/hash、当前获准范围、问题、可写路径及验收证据。需要共享分析数据时由一个执行者生成后再分派；互相依赖的任务排队，不能为并行提前跳阶段。
4. 简短报告本阶段实际分工；委派后保存真实任务标识，在项目报告中记录负责人、输入版本、结果路径和回收状态。等待所需结果再汇总。没有真实调用返回值和子任务结果时，不能声称“已由多个智能体审核”；不创建用户侧新聊天冒充子智能体。
5. 根据新疑点、任务完成、失败或资源变化调整分工。完成后回收结果；遇到分歧对照实际证据，不能按多数票决定剪点。并发数服从宿主上限；槽位暂满时等待或回收已完成任务，再安排质检。只有一个可用子智能体槽位也可在制作完成后安排未参与该版本制作的审查者。不为凑人数重复同一工作。

人数只服务当前任务。例如，多条原片可按视频拆分，单条复杂口播可按重说和剪点分工，局部字号修改可由主代理制作并交一个独立审查者核对受影响画面。这些是拆分示例，不是人数下限或固定上限。

## 各阶段安排

以下“等待确认”仅用于半自动；全自动完成本阶段实际 AI 质检后继续，沿用开工时绑定输入与设置的有效授权，不制造用户确认。

| 当前阶段 | 可分派的工作 | 主代理负责 |
| --- | --- | --- |
| 原片分析 | 气口与切点边界检查；口误、单字/词/半句/整句重说核对。多条原片也可逐条分工 | 一次生成或复用基础转写；合并候选，给拟删原片时间段、保留内容、理由与预计时长，等待方案确认 |
| 无字幕粗剪 | 产物完成后检查残留重说、有效发音是否被剪掉、全部剪点、音画时长和解码 | 由唯一执行者按获准时间线生成；根据问题修复并提交完整新版，等待粗剪确认 |
| 字幕 | 基于已确认粗剪分别检查文字与专名、发声同步与断句；渲染后检查实际字幕画面 | 维护一份字幕和时序，整合修改，生成完整字幕预览，等待字幕确认 |
| 人物蒙版 | 获准形状/背景后的布局、完整头发与脸、字幕间距检查；完整预览后的背景方向、循环和原声一致性复核 | 统一渲染设置和输出；先布局后完整 MP4，等待确认 |
| 剪映工程 | 对当前版本做一次基础完整性检查，复用构建/安装证据，核对主要轨道、素材路径、全时长和字幕 | 基础检查通过后确认成功导入剪映即交付；同一窗口一个操作者，不继续试改、保存重开或导出视频 |

表格是可选拆分维度，不要求每格固定创建一个代理。不是同时开启所有阶段。质检必须等待所查产物完成；字幕、蒙版和工程的制作仍受各自确认门禁约束。不同原片的删除区间、字幕映射与批准记录不能混用。

## 文件与资源协作

- 主代理是剪辑计划、阶段批准、项目设置及最终交付的唯一维护者。修改产物时明确指定一个执行者；审查者提交问题，不能同时改同一文件。所有写入继续遵守项目锁。
- 子智能体默认读取原片、共享转写和稳定产物，只写自己被分配的报告。可使用 `02_analysis/agent_reports/<video_id>/<stage>/<agent_id>/`；标识清理为 ASCII 小写、数字和下划线，每次报告使用新文件名，不覆盖用户文件。报告包含原片/产物时间坐标类型。
- 同一音轨的全量转写、依赖补装和模型下载只由一个执行者负责；其他任务等待并复用。局部重转写仅在确有疑点且当前范围允许时进行。不要让每个子智能体重复安装环境或同时加载多份大模型。
- FFmpeg 渲染、完整转写等重任务按 CPU/GPU/内存情况排队；多智能体并行分析不等于全部媒体进程同时启动。调用已有媒体入口，不重写临时业务管线。
- 对同一个剪映窗口或草稿，最多一个执行者进行 UI 操作；其他子智能体可检查已保存的稳定副本，不与用户抢占界面。

## 必做质检与反馈

分析方案，以及每个新制或修改的粗剪、字幕、蒙版预览、剪映工程都必须质检。工具可用时，必须安排至少一个未制作或修改该待验版本的子智能体承担独立检查；主代理负责确认覆盖完整，可以自主合并或拆分检查职责。审查者可以提出修复建议；若亲自修改了产物，该版本须交另一个未参与制作/修改的审查者，不能由修复者独自签验。

审查者读取当前版本的真实产物、输入与批准依据，报告：检查项、实际路径和 hash/版本、对应时间点、方法与覆盖范围、问题证据及尚未执行的项目。主代理不得只把自己的“已通过”结论交给审查者要求复述；多人查看同一份 ASR 文本仍不能证明原音没有重复。

在已有项目报告中保留一份简短质检记录即可，无需另建任务管理系统。记录阶段/视频、产物 hash、制作与检查者的真实任务标识、检查状态、证据路径、待修项及修复后的复查结果。状态区分 `passed`、`failed`、`unverified`；任务成功退出、候选为零或审查者没有返回问题，均不能自动记 `passed`。主代理核对该阶段检查项是否覆盖，遗漏项补查，不让用户填写报告。

具备音视频感知能力时才记录实际听看结果。若只读了字幕或静态 JSON，只能报告这些检查，不能说已经听校、没有吞字或剪映 UI 验收通过。半自动中子智能体质检不能替代用户阶段确认；全自动中 AI 质检按有效流程授权推进，不伪造人工批准。

实际修改后重新绑定版本/hash，针对变化与受影响范围复核；未变化部分可复用有版本依据的证据，失效报告不得沿用。未改动的媒体不重复全量转写，也不因普通剪辑而执行 Skill 升级或整套软件回归。

所需检查未完成、问题未处理或复查失败时，不作“已验收”交付、不推进依赖该验收的阶段。可以交标明问题的完整预览或原音供用户诊断、试听；用户负责的真实听校证据仍按既有阶段规则记录。剪映工程按 [导入即交付](jianying.md#基础检查与导入即交付) 收尾：两种模式都不继续试改、保存重开或原生导出，不主动问额外验收；无法确认真实导入时如实说明，不持续派相同检查。任务失败时先判断输入、工具或资源问题；同因失败且无新证据时停止重复派发，主代理接回可完成部分并说明缺口。

## 能力不可用

工具缺失、明确拒绝、调用实际失败且无法恢复，或用户明确要求单代理时：说明具体原因，主代理仍须完成可执行的检查，将独立子智能体质检记为 `unverified`，不模拟多个角色。临时槽位占满先按上文排队，只等待本任务已有且能够结束释放槽位的工作；若宿主根本没有子智能体容量，或没有可回收任务，不无限等待或重复创建。

降级不清除媒体警报，也不替代实际听校或 UI 验收。对应检查证据及本模式所需授权真实齐备时，可按原有阶段门禁推进，同时保留“主代理复核，独立子智能体质检未完成”的说明；不能宣称独立验收通过。缺实际检查证据时，只交待核产物并说明缺口。用户单代理要求优先，但不免除质检。

用户需要排查 Codex 时，读取其实际版本、会话工具与适用配置后再判断原因；不自动改全局配置。当前 Codex 的委派触发与可用性见 [官方子智能体文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)。安装本 Skill 不会为不支持委派的宿主增加工具。
