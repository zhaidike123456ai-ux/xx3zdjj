# 多智能体协作

这是视频处理阶段的默认工作安排；当前用户要求与宿主规则优先。使用宿主已有的子智能体工具，不把 Skill 的 `agents/openai.yaml` 当成能开启多智能体的开关。它只提供技能界面元数据与默认提示，不创建自定义代理。

## 启动与分工

1. 核对实际加载的 Skill 路径、版本、当前阶段、批准状态，以及会话工具中是否有创建、等待和收集子智能体结果的能力。工具名称随宿主变化，以实际暴露的接口为准；不要虚构函数名或把未暴露的能力说成已开启。
2. 有可独立任务时调用创建工具，把任务真正交给子智能体。每次委派说明：输入绝对路径、版本/hash、当前获准范围、问题、可写路径及验收证据。需要使用共享分析数据时先由一个执行者生成，完成后再分派。
3. 简短报告实际分工和子智能体标识；在项目报告中保留任务标识、负责人、输入版本、结果路径和回收状态，等待对应结果再汇总。无需复制大量内部日志。没有真实创建返回值和子任务结果时，不能声称“已由多个智能体审核”；不创建用户侧新聊天冒充子智能体。
4. 并发数服从宿主上限与本机资源，通常先分派两个互相独立的分析任务，回收结果后再安排产物质检。达到上限时先等待本任务已运行的子任务完成，再分派下一项；一个可用槽位可串行创建独立审查者。不为凑人数重复同一项工作。

## 各阶段安排

| 当前阶段 | 可分派的工作 | 主代理负责 |
| --- | --- | --- |
| 原片分析 | 气口与切点边界检查；口误、单字/词/半句/整句重说核对。多条原片也可逐条分工 | 一次生成或复用基础转写；合并候选，给拟删原片时间段、保留内容、理由与预计时长，等待方案确认 |
| 无字幕粗剪 | 产物完成后检查残留重说、有效发音是否被剪掉、全部剪点、音画时长和解码 | 由唯一执行者按获准时间线生成；根据问题修复并提交完整新版，等待粗剪确认 |
| 字幕 | 基于已确认粗剪分别检查文字与专名、发声同步与断句；渲染后检查实际字幕画面 | 维护一份字幕和时序，整合修改，生成完整字幕预览，等待字幕确认 |
| 人物蒙版 | 获准形状/背景后的布局、完整头发与脸、字幕间距检查；完整预览后的背景方向、循环和原声一致性复核 | 统一渲染设置和输出；先布局后完整 MP4，等待确认 |
| 剪映工程 | MP4 已确认且工程生成后，检查轨道、素材路径、全时长和编辑结构；界面操作由一个执行者进行 | 保护旧草稿，协调导入、打开、编辑、保存重开和原生导出；汇总已验证与未验证项 |

不是同时开启所有阶段。质检必须等待所查产物完成；字幕、蒙版和工程的制作仍受各自确认门禁约束。不同原片的删除区间、字幕映射与批准记录不能混用。

## 文件与资源协作

- 主代理是剪辑计划、阶段批准、项目设置及最终交付的唯一维护者。修改产物时明确指定一个执行者；审查者提交问题，不能同时改同一文件。所有写入继续遵守项目锁。
- 子智能体默认读取原片、共享转写和稳定产物，只写自己被分配的报告。可使用 `02_analysis/agent_reports/<video_id>/<stage>/<agent_id>/`；标识清理为 ASCII 小写、数字和下划线，每次报告使用新文件名，不覆盖用户文件。报告包含原片/产物时间坐标类型。
- 同一音轨的全量转写、依赖补装和模型下载只由一个执行者负责；其他任务等待并复用。局部重转写仅在确有疑点且当前范围允许时进行。不要让每个子智能体重复安装环境或同时加载多份大模型。
- FFmpeg 渲染、完整转写等重任务按 CPU/GPU/内存情况排队；多智能体并行分析不等于全部媒体进程同时启动。调用已有媒体入口，不重写临时业务管线。
- 对同一个剪映窗口或草稿，最多一个执行者进行 UI 操作；其他子智能体可检查已保存的稳定副本，不与用户抢占界面。

## 独立质检与反馈

审查者读取当前版本的真实产物和批准依据，报告：检查项、实际路径和hash/版本、对应时间点、问题证据及尚未执行的项目。主代理不得只把自己的“已通过”结论交给审查者要求复述。

具备音视频感知能力时才记录实际听看结果。若只读了字幕或静态 JSON，只能报告这些检查，不能说已经听校、没有吞字或剪映 UI 验收通过。子智能体质检不能替代用户的阶段确认。

实际修改后重新绑定版本/hash，针对变化与受影响范围复核；失效报告不得沿用。未改动的媒体不重复全量转写。任务失败时先判断是输入、工具或资源问题；同因失败且无新证据时停止重复派发，主代理接回可完成部分并说明缺口。

## 能力不可用

如果创建工具缺失、明确拒绝或资源上限阻止创建：说明实际证据和当前影响，继续单代理顺序处理可完成部分。仍按阶段规则等待用户确认，交付时将“独立子智能体质检”记为未执行，不能模拟多个角色冒充独立验收。

用户需要排查 Codex 时，读取其实际版本、会话工具与适用配置后再判断原因；不自动改全局配置。当前 Codex 的委派触发与可用性见 [官方子智能体文档](https://learn.chatgpt.com/docs/agent-configuration/subagents)。安装本 Skill 不会为不支持委派的宿主增加工具。
