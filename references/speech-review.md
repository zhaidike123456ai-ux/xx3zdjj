# 重说检测、警报与机器证据复核

v2.2.2 起全自动与半自动都使用机器证据质检，不要求实际听音频能力，也不专门要求用户听校。机器结论须标明范围，不能宣称已经听过或保证完整音素与听感。

## 检测与删除分开

`analyze` 始终执行长句、短片段和有效开场检测，`retake_policy=none` 只是不提出重说删除范围，不能关闭检测。`last_complete` 也不能证明最后一遍完整，不能直接拿 ASR 词时间切字。正常叠词、强调和排比允许保留，必须记录为什么保留，不能机械删。

`--single-pass` 只跳过第二路全片转写，不跳过开场分窗。同一模型两路全片 ASR 一致，不构成没有重说的独立证据。

## 有效开场

先从 16 kHz PCM 音频找实际活动段，并与首个 ASR 词交叉定位。前导静音可能很长；检查文件 0–2 秒并不等于检查人声开头。声学阈值可能漏掉弱音，因此窗口同时保护更早的 ASR 起点，不把低能量自动视为无发音。

开场使用首活动段隔离窗、第二活动段上下文窗、两段合并窗及重叠上下文窗。每个窗口独立解码，记录原片时间和覆盖范围。不同窗口覆盖同一次发声时，不能将两个相同词拼成两次重说。短活动段与相邻起音之间存在疑点时，即使 ASR 仍省略重复，也留下局部语音证据复核警报。

窗口与声学活动只是定位证据。气口、弱声母、自然叠词和刻意强调结合独立分窗转写、上下文、词时间和声学边界审查；证据不足时保守保留并记录具体处理，不能机械删除或统一判误报。候选不自动产生删除授权。任何示例时间都只适用于该例。

## 机器状态与警报

`review-report.json` 每项检查分别保存：

- `status`: `executed` / `skipped` / `unavailable`，即实际运行、跳过或不可用。
- `result`: `passed` / `review_required` / `failed` / `unverified`，即检查结论。
- `coverage`、`method`、`reason`：覆盖哪段、如何检查及未完成原因。

`command_status=completed` 或退出码 0 仅表示命令运行完成。`quality_status` 独立记录机器质检状态。零候选、成功解码、音轨相似或时长一致都不能单独证明没有口误、吞字或重说。`word_integrity` 检查词时间有效性、边界保护、覆盖及剪辑谱系，不保证真实完整音素或听感。实际听校单列 `not_required`；不能因为机器没有听音频能力而把这些可执行的机器检查填成 `unavailable/unverified`。

检测脚本输出 `executed/unverified` 表示检测已完成、尚待 AI 审查证据，并非要求实际听校。执行代理继续读取报告与相关机器证据，完成警报处置和有明确覆盖范围的 `check_resolutions`；全自动据此继续，半自动照常取得阶段确认。不要仅因检测结果尚未签验就结束整个任务，也不要直接改写原检测报告为通过。

每个警报有稳定 ID，`review_required=true` 必须有处理记录。不能把异常长单字解释为“时间偏差”后自行消警；先完成重叠窗口的机器转写、时间与声学活动复查，再记录证据。真实检测失败、未解决警报仍阻断进入字幕；无实际听校本身不阻断。未解决时可交标注待核的完整预览，但不得宣称已修复。

## 解码时间与媒体时间

解码后的 PCM/WAV 可能比 MP4 时间线稍长。`parse_silence` 在公共入口将静音起止限制到 `[0, media_duration]`，重算持续时间，丢弃空区间或倒序区间。不要只改最终警报、放宽门禁容差，或让用户为非法坐标作确认。

`silence-measurements.json` 保存原始 FFmpeg 日志、逐项原始时间/原始报告时长、裁剪差值，以及被丢弃的填充区测量。实际 WAV 帧数与采样率独立测得解码时长；较大差异生成技术复核警报。当前阈值为媒体时长的 0.1%，下限 100 ms、上限 500 ms；这是诊断阈值，不是任何编码器都安全的保证。正常填充修正不消除原有气口或局部复核警报，也不构成吞字证据。

## 异常词与分窗完成状态

单个词 `start == end`、倒序、缺失、非有限值或超出解码窗口时，只把该词列为 `timing_unverified`。保留 `raw_output`、正常 `words`，异常项记录窗口 ID、词索引、原始局部和换算后的原片时间及原因。不能补造时长，也不能用过滤异常后的词表宣称整窗已通过。

异常词警报使用已知合法的**复核窗口**作为范围，明确 `scope_type: review_window_not_word_boundary`；该范围不是异常词真实起止。粗剪声学证据另行核验，字幕入口拒绝无效或已标记未验证的词时间。

开场报告同时输出：

- `scheduled_windows / completed_windows / failed_windows`：原计划窗总数、完整成功数、失败或时间证据不完整数。
- `temporal_coverage_complete`：完整成功窗的时间并集是否覆盖计划区域。
- `multiscale_complete`：原计划每一种窗口是否都完整成功。
- `quality_status`：机器证据是否充分、是否仍需复核；解码全成功也不等于语音机器质检全部通过。

所以 8 窗中 7 窗完整、1 窗时间异常时，时间覆盖可以是 true，多尺度完成仍是 false，状态保持 unavailable/review_required。主流程最多追加 1 次扩窗解码，使用新的区间缓存键；原失败与异常警报仍保留，重试结果单列，不能改写原成功计数。

取得新窗口转写、合法词时间、声学边界和覆盖证据后，可按实际结论处理疑点并补核未覆盖的机器检查，无需追加实际听校。旧的异常时间仍不能用于字幕，需要重新取得有效时间。真实解码错误也必须保留，不能归为已处理的词时间异常。

## 用户反馈后的专项复查

用户说“重复”“吞字”“断句”时，先确定当前媒体版本和对应原片范围，比较两者的局部独立转写、词时间、声学活动与剪辑映射。不能拿旧全片转写反驳用户，也不能只扩大首尾保护范围就宣布修复；不把用户额外听校设为机器复查的前提。

`local-review` 的显式窗口会增加重叠上下文。传 `--feedback` 时须同时传 `--reference-source` 与 `--reference-window`，分别保存当前成片和原片报告、hash；时间依照 edit-map 换算，不把原片秒数直接当成片秒数。

```bash
python scripts/run_pipeline.py local-review \
  --source /path/to/current.mp4 --output-dir /path/to/current_review \
  --model /path/to/local_model --window START:END \
  --feedback "用户指出开头单字重复" \
  --reference-source /path/to/original.mp4 --reference-window ORIGINAL_START:ORIGINAL_END
```

这些是由代理填写的参数模板，用户不需要组织命令。先核对每条素材的活动段、转写与映射再选择范围，不使用固定示例剪点。

## 修复与关闭警报

粗剪 `edit-map.json` 保存原片分析报告及成片 hash。`residual-check` 检查当前成片的全片、有效开场与静音，并把原片警报映射到保留声音；已经删除的警报映射到删除后衔接位置，后验核对起点的词时间、声学边界和保留范围。不能通过复制成片、丢掉 edit-map 或换个报告目录来绕过原片警报。

保持成片、edit-map 和被引用的分析报告一起可访问。旧版缺少这些记录时，重新分析、生成新版粗剪与残留报告；旧的“全通过”计数不能替代新证据。

保留正常叠词或确认误报时，用[机器证据协议v2](review-evidence-v2.md)记录 `decision: retain` 与 `verification: confirmed_benign`；不确定保留须写 `verification: inconclusive`，仍属于未决。证据绑定当前媒体、警报/检查与覆盖范围，说明局部转写、上下文和映射为何支持结论；不能只写“没有问题”。新协议不要求实际听校，不能自动把所有警报归为误报。

需要修改的警报不能在同一旧报告里写 `fixed` 消除。先修媒体，再运行新残留检测；旧报告与旧确认失效。机器未覆盖部分须取得对应范围的实际机器证据，不能用静态文件结构代替语音检查。旧听校记录只在原有证据与能力声明真实且满足兼容校验时保留；缺失或虚假的旧听校记录不能只补一个证据 kind 放行，须对受影响范围重新做机器审查并生成新方法与证据。未改媒体可复用有效缓存，不为更换报告方法全片重剪。
