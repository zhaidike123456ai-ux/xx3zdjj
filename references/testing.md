# 测试与验收

## 自动测试

在Skill外的临时目录运行测试，避免写私人项目。测试名称/数量/结果以真实运行报告为准。

- test_studio_manager.py：ASCII路径、原片保留、项目冲突、偏好层级、资产去重和固定副本、上游变化使确认失效、锁。
- test_runtime.py：环境发现、平台分支、安装复用和失败恢复。mock下载安装不等于Windows真实安装。
- test_retake_detection.py、test_media_quality.py：短重说/正常重复、缓存、字幕对齐阻断、局部复核和媒体合成。构造词表测试不是识别准确率。
- test_rough_cut_portability.py：合成媒体实际删除/帧率、hash、非法删除阻断。
- test_opening_review.py：前导静音、多尺度窗口、九个正常词加零时长词、原始证据保留、时间覆盖/分窗成功区别和有限重试；合成波形不是人声识别准确率。
- test_silence_media_bounds.py：24.05 秒媒体与 24.064 秒解码填充、完全填充区、未闭合尾部静音、原测量审计与异常大时差。
- test_analysis_to_captions.py：真实合成媒体实际分析、粗剪、残留检测和字幕 CLI；完整证据进入 SRT，缺证据/确认/来源或过期版本仍阻断。ASR 和审查记录是明确标注的模拟夹具；同时覆盖机器证据无需听校即可推进，以及历史听校记录兼容，不冒称真人验收。
- test_retake_pipeline.py、test_review_pipeline.py：默认策略不禁用检测、单次全片仍分窗、首尾提议边界、帧量化后字头保护、零候选仍未验证、反馈双源对照。
- test_review_state.py：报警与版本闭环、实际证据要求、上游来源与多分片覆盖；模拟听校夹具不代表真人听过。
- test_stage_gate.py：批准版本、证据、未解决项对后续阶段的阻断。
- test_workflow_mode.py、test_studio_workflow.py：模式选择、一次授权、暂停/恢复、配置与来源绑定、全自动 AI 证据、半自动确认、工程基础检查同标准和冻结证据。
- test_full_auto_pipeline.py：合成媒体真实经过粗剪、字幕、蒙版、原生工程生成及临时草稿目录安装；覆盖设置/计划/声学证据变化阻断。ASR 与 AI 机器审查记录均为明确的模拟夹具，无音频感知 capability 或听校证据要求；临时目录安装不代表剪映 UI 导入。
- test_jianying_adapter.py：草稿结构、唯一ID、时长覆盖、批准hash、冲突保护、密文快照。

## 真实媒体

全自动与半自动执行相同的机器媒体检查。保留原片对照，结合有效发声开头的分窗（包括前导静音后的首次起音）、词时间、声学活动和剪辑映射，核对所有剪点与结尾、失败尝试残留、否定条件、停顿和异常波形。实际听校单列为 not_required，不因没有音频感知能力停止流程。ASR 文本或字符覆盖率不能单独保证完整音素；机器结论限定在实际覆盖范围，真实检测失败与未处理警报仍不得通过。

字幕逐句比对稿件、局部转写和有效词时间，检查每条边界、最长条、孤立尾字、真实字形大小与人物间距。蒙版检查首帧和每段主体活动，背景独立、比例正常、覆盖全长；动效方向和速度来自本次确认。

## 剪映工程

两种模式的默认交付条件相同：一轮基础完整性检查通过，并确认完整工程已被剪映实际识别导入。基础检查核对文件与素材引用、全长和主要轨道、字幕时序及已验版本对应；复用同版本已有的构建/安装证据，不重复整套扫描。详见 [剪映适配](jianying.md)。

复制到草稿目录仅证明文件放置完成，不等于应用识别。记录当前完整工程的识别证据和版本；没有 UI 能力或尚无可靠的应用识别证据时报告“基础检查通过，导入待确认”并给现有路径，不宣称交付条件已满足，不无限重试。基础检查失败只修复已定位问题，并复查受影响范围。

默认不试改、不保存重开、不从剪映导出 MP4，也不主动询问深度验收。只有用户另外明确要求时，在验收副本执行所选检查：试改字幕/蒙版/切点/背景、保存重开或原生导出。完成一轮或遇到明确阻塞即报告，不重复检查已通过且未变的内容。FFmpeg 独立预览不能证明剪映工程显示或原生导出结果。

pilot只证明兼容测试，full须匹配批准媒体全长/帧数/字幕/切段。密文草稿不能用旧明文覆盖。精剪中间片再分段不等于原片级无损编辑。

在用户另行授权的兼容探索内，同一具体问题最多两轮针对性尝试；无新证据就报告阻塞，继续换路线按用户选择，不自动延长验收。Windows文件结构测试不代表Windows剪映UI通过；Mac一台通过不代表所有版本通过。

## 状态

报告分通过/失败/未验证/等待输入，分别记录 Skill 结构、环境、模型推理、机器媒体检查、字幕渲染、原生静态结构、剪映识别导入，以及额外要求的编辑/保存重开/导出。全自动的阶段通过记录为 `ai_review`，绑定有效授权、实际产物 hash 和检查证据，不伪填 `user_approval`；半自动另保留用户对对应版本的确认。实际听校不是必需项；已有真实听校记录可以保留，但新机器记录不能虚构已听过。机器检查使用 combined_evidence_review 或 machine_evidence_review，警报处置必须带当前版本、范围、具体结论及 machine_verification 哈希证据。

开发审计结果保存在工作区，不把本机路径、私人素材、授权或动态通过结论写成通用前提。真实项目仍需检查环境与对应证据。

## 协作指令的维护验收

修改分派、模式或质检指令时，让未编写该改动的审查者用具体场景演练：首次选模式与未回答、全自动一次选齐选项、输入/设置变化使授权失效、多视频共享转写、单槽位、局部修改、工具缺失、过期质检报告、基础检查后剪映识别导入和复制成功但应用未识别。同一剪映窗口只有一个操作者。核对全自动能按有效授权和每阶段真实 AI 质检连续推进、半自动保留阶段用户确认、两种模式采用同一结束标准，且不主动询问或执行深度验收；发现冲突后修正再复查。该演练只检验指令决策，不等于实际运行了视频流程、听过原音或操作过剪映。

仅修改协作指令不必重跑媒体推理；检查 Skill 结构、引用和发布包完整性，并确认脚本与素材未被意外修改。不得把上一版的媒体测试数量写成新版重新执行的结果。

## 可选真实开场回归

`test_real_opening.py` 默认跳过，仓库不分发私人素材。仅对已经标注含开头重说的样本使用，不能拿任意正常视频运行并据此判断准确率。设置环境变量 `XX3ZDJJ_REAL_RESTART_SOURCE`、`XX3ZDJJ_REAL_RESTART_TRANSCRIPT`（含匹配 source_sha256 的全片缓存）、`XX3ZDJJ_REAL_RESTART_MODEL`（已安装本地模型），可选 `XX3ZDJJ_REAL_RESTART_EXPECTED_TOKEN`（默认“我”）与仓库外 `XX3ZDJJ_REAL_RESTART_OUTPUT`，运行：

```bash
python -m unittest discover -s scripts -p 'test_real_opening.py' -v
```

测试会实际执行有上限的开场短窗，要求合并短窗暴露标注重复、产生待复核候选、缺 ASR 时明确 unavailable，并核对原片 hash 不变。不会剪片或下载模型；需要安装好的 FFmpeg/FFprobe 和 faster-whisper。测试通过只证明该标注样本被发现，不能证明任意口误均被检出或成片已经完成听校。

可选零时长词真实回归：在上述私有样本环境之外设置 `XX3ZDJJ_REAL_TIMING_WINDOW=START:END`，并设置已标注的 `XX3ZDJJ_REAL_TIMING_WORD`（默认“上”）。测试必须实际复现该词时间异常，保留其他正常词与完整原始输出，不能以简单放行 unavailable 当作通过；不提供窗口时明确跳过。不同模型/系统未复现该异常时会报告失败而非捏造证据。

新旧测试的文本读写显式使用 UTF-8，Windows 的默认 GBK 不再决定中文夹具编码。跨平台分支与编码检查不等于 Windows 实机或真实听校已经验收。
